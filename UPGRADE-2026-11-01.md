# Part 2 — The Critic + one-click start (2026-11-01, later)

## The Critic (runners/critic.js)
Runs after any ministry writes files. Cheapest layer first:
1. **Law checks** (plain code, $0): nearly-empty file, placeholder/CONTINUED markers, unclosed code block in .md,
   bad JSON, syntax check for .js/.py/.sh, unclosed braces in code. Any hit = FAIL, model never called.
2. **Critic model** (Haiku 5.5, ~$0.0004 a review): sees ONLY the task as assigned + the files. Never the ministry's reasoning.
   Returns PASS/FAIL + up to 3 problems. Advises only, can't edit.

Verdict is appended to the ministry's reply and stored on the task row (critic_verdict, critic_notes, critic_fails).
Chancellor may re-dispatch with the problems. Cap: 3 attempts per ministry per task (original + 2 revisions),
then the task is FAILED and lands on the Emperor. This also fixes an old bug: retries and // CONTINUED: follow-ups
used to be silently blocked by the Warden.
Settings in data/imperium-registry.json -> "critic": { model, enabled, max_revisions }.

Run against the existing output folder, Law checks alone caught: the cut-off unity2d-reference.md, agent chatter
pasted inside veilborn_gdd.md, a Python file with prose and a made-up 'norsecraft' library, and four near-empty test files.

Mock tests: PASS path, FAIL->fixed on revision 2, and hopeless->stopped at the cap. All three behaved.

## Startup
- **One click:** run `Make-Desktop-Shortcut.bat` once. Then double-click "Norse Imperium" on the Desktop.
- **What it does:** Imperium.bat -> WSL -> start-imperium.sh -> stops leftovers (Imperium's only) ->
  preflight.js (Node 22.5+, API key, registry, SOULs, databases, code compiles, leftover queue, key + models live with a free API call)
  -> web terminal on http://localhost:7878 (browser opens) -> Warden.
- **Stop:** Ctrl+C or close the window. Both shut everything down.
- **By hand:** `bash /mnt/c/Imperium/start-imperium.sh`
- **Offline:** `IMPERIUM_SKIP_API_CHECK=1 bash /mnt/c/Imperium/start-imperium.sh`
- **Leftover work from last time:** `node send.js --clear`
